AI tools do better with Markdown than with HTML. dockudos serves your docs to them three ways, generated from the
same files as the site, so they never drift.

## llms.txt

`/llms.txt` is an index of the docs, following the [llms.txt](https://llmstxt.org) format: the site name, a summary
(`seo.description`), then a link per page, grouped by the groups of your navigation. Each link goes to the page's
Markdown twin and carries its description.

```text
# Acme Docs

> Everything about the Acme API.

## Start

- [Quickstart](https://docs.acme.com/quickstart.md): Make your first request
- [Authentication](https://docs.acme.com/guides/auth.md)

## Optional

- [Changelog](https://docs.acme.com/changelog.md)
```

Pages your navigation does not list go under "Optional", which tools may skip when they are short of room.
Links are absolute when `seo.siteUrl` is set.

`/llms-full.txt` is the whole documentation in one file: every page's Markdown, each headed by its title and
`Source:` address. Use it for tools that want everything in a single fetch.

Both are built when the site is built. `dockudos init` creates their routes (`src/app/llms.txt/route.ts` and
`src/app/llms-full.txt/route.ts`); for an existing site, add them:

```ts title="src/app/llms.txt/route.ts"
import { createLlmsHandler } from '@dockudos/next/llms';

export const dynamic = 'force-static';
export const GET = createLlmsHandler();
```

## Markdown twins

Every page is available as Markdown at its own address with `.md` added, and from its own address when the request asks for
Markdown:

```bash
curl https://docs.acme.com/guides/auth.md
curl -H "Accept: text/markdown" https://docs.acme.com/guides/auth
```

The home page is `/index.md`. The Markdown has the page's title and description, then its content with
`<include>`s expanded and frontmatter removed. [`<Visibility for="agents">`](../components/visibility.mdx) blocks are
included and `for="humans"` blocks are left out, so you can write extra context just for AI tools.

Every component writes itself as plain Markdown, not as a tag: a callout becomes a quote (`> **Warning: Title:** ...`), tabs and
steps become bold lines (`**npm**`, `**1. Install**`), a card becomes a link, `<Kbd>` becomes code, `<Endpoint>` becomes
`` `GET /pet/{id}` ``, and a `<TypeTable>` or `<AutoTypeTable>` becomes a table. Code is never touched.

### Your own components

A component says how it reads as Markdown with a `toMarkdown` property, the way an object says how it reads as a string with
`toString()`. It gets the props as written and its content already converted, and returns Markdown:

```tsx title="components/pricing-note.tsx"
import { md, type ToMarkdown } from '@dockudos/core';

export function PricingNote({
  plan,
  children,
}: {
  plan: string;
  children: React.ReactNode;
}) {
  return <aside className="pricing-note">{children}</aside>;
}

PricingNote.toMarkdown = ((props, children) =>
  md.quote('Pricing', props.plan, children)) satisfies ToMarkdown<{
  plan: string;
}>;
```

`md` has the small pieces (`block`, `section`, `bold`, `code`, `link`, `table`, `quote`, `item`), and `container` for a component
that only groups what is inside: `Row.toMarkdown = md.container`. The third argument says where the component sits: its
`index` among siblings, the names of its `parents`, the page's `headings`, and `fence()` for a code block that must not be
converted again. Return `undefined` to keep the tag as written. A component without `toMarkdown` keeps its content, and its
title if it has one.

The built-in components need nothing. To use your own, pass them where the Markdown is served:
`createMarkdownHandler({ components })`, `createDocsApi({ components })`, `createLlmsFullHandler({ components })` and
`createMcpHandler({ components })`, with the same object you give `defineMdxComponents()`.

`withDocs()` sets up the rewrites; the content comes from the markdown route (`/api/markdown`, which `dockudos init` creates and the
[catch-all API route](./search.mdx#the-routes) also provides). Files, `/api/*` and `/_next/*` are never rewritten.

<Callout type="note" title="Caching">
  The HTML and Markdown of a page share one address. A CDN that caches by
  address alone can hand Markdown to a browser or the reverse. Make it vary on
  the `Accept` header, or point tools at the `.md` address, which is distinct.
</Callout>

## What is left out

Hidden pages (`hidden: true`) and pages behind an [access rule](./protecting-pages.mdx) are never in `llms.txt`,
`llms-full.txt`, the search index or any other listing. A hidden page can still be fetched at its own address, as it can in
a browser. A protected page's Markdown twin needs the same credentials as the page.
