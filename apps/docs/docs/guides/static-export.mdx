```bash
npx dockudos build --static
```

writes the whole site to `out/`. Upload that folder to GitHub Pages, Netlify, Cloudflare Pages, S3 or any file server.

For a host that serves your site from a sub-path, such as a GitHub Pages project site at `https://you.github.io/docs/`:

```bash
npx dockudos build --static --base-path /docs
```

## What works

- Every page, the navigation, themes, code blocks, diagrams, math and the API reference.
- Search in the browser. The index is written to `out/api/search/index`, and on a site with [versions or languages](./versions.mdx) one file for each (`index-v1~fr`), so search stays inside the version and language of the page.
- A [social card](./seo.mdx#social-cards) for every page, drawn into `out/og/`.
- "Copy page" and a `.md` file next to every page (`/guides/search.md`).
- `llms.txt`, `llms-full.txt`, the sitemap and `robots.txt`.
- [Redirects](/guides/redirects) from `docs.json`, as small pages that send the visitor on. Redirects that use patterns (`:id`, `*`) cannot be written; add them to your host's own redirect rules.

## What is left out

These need a server, so a static build does not include them, and hides their buttons:

- The assistant, AI navigation, and the MCP server.
- Page feedback (kudos).
- Access rules. A static site cannot keep a page private, so the build **leaves the pages they cover out**: no page, no Markdown twin, nothing in the search index, `llms.txt`, the sitemap or the social cards. The build says how many it left out.
- The API playground's optional proxy. The playground itself still works, as it sends requests from the browser.

The same project still builds as a normal Next.js site with `dockudos build`. Nothing in your files changes between the two.

## Page dates

"Last updated" comes from Git history. CI checkouts are shallow by default, which gives every page the same date. In GitHub Actions use `fetch-depth: 0` on `actions/checkout`.
