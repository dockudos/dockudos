dockudos builds a documentation site from a folder of MDX files and one `docs.json`. It runs inside
a Next.js App Router project, so you keep the whole Next.js toolbox. This guide covers authoring,
theming, components and the CLI.

## How it works

You write three kinds of files. dockudos does the rest.

<Tree>
  <Tree.Folder name="my-docs" defaultOpen>
    <Tree.Folder name="docs" defaultOpen>
      <Tree.File name="index.mdx" />
      <Tree.File name="first-page.mdx" />
    </Tree.Folder>
    <Tree.File name="docs.json" />
  </Tree.Folder>
</Tree>

- **Pages** are MDX files in `docs/`. The URL is the file path without the extension. The title and
  description come from frontmatter.
- **`docs.json`** holds the site name, theme, navigation and other settings. List pages in
  `navigation`, or leave it empty and the sidebar follows your folders.
- **Components** such as callouts, tabs and steps are available in every page without imports.

See [Project structure](./getting-started/project-structure.mdx) for every file and folder.

## What you get

- **Navigation you control.** Tabs, groups and nested groups, or the folder layout as a fallback.
- **A real theme.** One brand color generates a palette for light and dark mode that meets WCAG AA
  contrast. Six layouts, switchable per site or per page.
- **Components for docs.** Callouts, tabs, steps, cards, file trees, type tables, diagrams, math and
  more. See the [component overview](./components/index.mdx).
- **Feedback from readers.** A thumbs up or down and an optional comment under every page, read
  with `dockudos kudos`. See [Kudos](./components/kudos.mdx).
- **Checks that fail the build.** An invalid `docs.json` or a broken link stops `dockudos build`
  and names the file and line.
- **A headless core.** Config validation, the page tree, breadcrumbs and the table of contents work
  without React. See [the headless core](./reference/headless-core.mdx).
