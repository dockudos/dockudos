A callout is a highlighted aside. Use it for the one thing a reader must not miss; if every other
paragraph is a callout, none of them are.

## Types

<Callout type="note">A plain note. This is the default type.</Callout>
<Callout type="info" title="Good to know">
  Information the reader may not expect.
</Callout>
<Callout type="tip">A shortcut or a better way.</Callout>
<Callout type="check">It worked, or this is done.</Callout>
<Callout type="warning">Something that can go wrong.</Callout>
<Callout type="danger">Something that cannot be undone.</Callout>

```mdx
<Callout type="info" title="Good to know">
  Information the reader may not expect.
</Callout>
```

| Type      | Use it for                                              |
| --------- | ------------------------------------------------------- |
| `note`    | A side remark that is safe to skip.                     |
| `info`    | Context the reader may not have.                        |
| `tip`     | A faster or better way of doing the same thing.         |
| `check`   | A success state, or "you should see this by now".       |
| `warning` | Something that can go wrong, or a common mistake.       |
| `danger`  | Data loss, security, or anything that cannot be undone. |

## Markdown containers

The same callouts can be written with colons, which reads better in long Markdown pages. The text in
brackets is the title. Containers exist for `note`, `info`, `tip`, `warning` and `danger`; use `<Check>`
for a check.

```mdx
:::tip[Shortcut]
Press `?` to see every keyboard shortcut.
:::

:::warning
No title: the type's name is used.
:::
```

:::tip[Shortcut]
Press `?` to see every keyboard shortcut.
:::

:::warning
No title: the type's name is used.
:::

## Shorthands

`Note`, `Info`, `Tip`, `Check`, `Warning` and `Danger` are the same callouts under shorter names, so
content written for other documentation tools works unchanged. They take every prop of `Callout`
except `type`.

<Tip>Shorter to write.</Tip>
<Warning title="Careful">This deletes the project.</Warning>
<Check icon="rocket" title="Launched">
  Everything is set up.
</Check>

```mdx
<Tip>Shorter to write.</Tip>
<Warning title="Careful">This deletes the project.</Warning>
<Check icon="rocket" title="Launched">
  Everything is set up.
</Check>
```

## Custom title and icon

`title` replaces the default heading. `icon` replaces the icon with any [icon name](./icons.mdx) (built in, or
from your own packs), or with an element:

<Callout type="tip" icon="sparkles" title="Heads up">
  Content can use **Markdown**, `code` and even other components.
</Callout>

```mdx
<Callout type="tip" icon="sparkles" title="Heads up">
  Content can use **Markdown**, `code` and even other components.
</Callout>
```

## Accessibility

A callout is a `role="note"` region and its heading is real text. The icon is decorative and hidden
from screen readers, so the meaning is always carried by the title and the words, never by color alone.

## Printing

Callouts keep their colored border on paper and are not split across two pages where that can be avoided.

## Theming

The colors are CSS variables: `--dk-callout-note`, `--dk-callout-info`, `--dk-callout-tip`,
`--dk-callout-warning` and `--dk-callout-danger`. `check` shares the green of `tip`. Override them in your CSS to
match a brand; see [Theming](../guides/theming.mdx). [Badge](./badge.mdx) uses the same palette.
