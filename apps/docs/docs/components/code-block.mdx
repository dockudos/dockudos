Every fenced block in your Markdown is rendered by the `pre` component, which is the `CodeBlock` of `@dockudos/ui`.
You almost never write it by hand; the [Code blocks guide](../guides/code-blocks.mdx) covers what goes in the fence
(titles, highlighted lines, diffs, `package-install`, `ts-to-js`, Twoslash). This page is about the component itself.

```ts title="hello.ts"
export const hello = 'world';
```

## What it gives you

- A frame with an optional title bar, taken from the fence's `title="…"`.
- A **copy button**, a real button named "Copy code". It copies the block's text without the lines marked as removed
  (`[!code --]`) and without Twoslash popups, and tells screen readers "Copied to clipboard" or "Copy failed".
- Light and dark highlighting at once, so switching theme does not redraw anything.
- A keyboard-focusable scroll area when a line is wider than the page, so a keyboard user can scroll it.

On paper the copy button is left out and long lines wrap, instead of scrolling. Code always uses the light theme in print.

A `<pre>` that did not come from a highlighted fence, such as one you write by hand or one inside a Twoslash popup, is
left plain: no frame and no copy button.

## Replace it

Replace `pre` in `mdx-components.tsx` to change every code block. Wrap `CodeBlock` to keep what it does:

```tsx title="mdx-components.tsx"
import { defineMdxComponents } from '@dockudos/next/mdx-components';
import { CodeBlock } from '@dockudos/ui';
import type { ComponentProps } from 'react';

const Pre = (props: ComponentProps<typeof CodeBlock>) => (
  <div className="my-wrapper">
    <CodeBlock {...props} />
  </div>
);

export const useMDXComponents = (components) => ({
  ...defineMdxComponents({ pre: Pre }),
  ...components,
});
```
