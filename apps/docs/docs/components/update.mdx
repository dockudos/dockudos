`Update` is one entry of a changelog. Stack several, newest first, to make a changelog page or a "What's new" section.

<Update label="1.2.0" date="2026-03-05" tags={['Added', 'Fixed']}>

- Added the kudos widget.
- Fixed the sidebar scroll position on long pages.

</Update>

<Update label="1.1.0" date="2026-02-10" tags={['Breaking']}>
  Renamed `docs.theme.accent` to `docs.theme.primary`.
</Update>

```mdx
<Update label="1.2.0" date="2026-03-05" tags={['Added', 'Fixed']}>

- Added the kudos widget.
- Fixed the sidebar scroll position on long pages.

</Update>
```

Leave a blank line after the opening tag and before the closing one when the body is a list, so it is read as Markdown.

## Date and label

`date` is `YYYY-MM-DD`. It is shown as a long date, such as "March 5, 2026", and kept machine readable in a `time` element, so
it is the same for readers anywhere. A date that is not in that form is shown as you wrote it. `label` is free text: a version,
or a name such as `March release`. Only `label` is required.

## Tags

A tag named `Breaking` (in any case) is red, any other is blue. Use a few consistent names: `Added`, `Changed`, `Fixed`,
`Removed`, `Deprecated`, `Security`, `Breaking`.

On wide screens the label, date and tags stay in view beside a long entry as you scroll through it. Each entry is an `article`
whose label is a heading, so readers using a screen reader can jump between releases.
