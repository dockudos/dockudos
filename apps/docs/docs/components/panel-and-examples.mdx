On a wide screen a `Panel` sits in the right-hand column, in place of "On this page", and stays in view as you
scroll. On a phone, and on paper, it is just part of the page. This page uses one.

Blank lines around the code blocks are what make them code blocks inside the components.

- `RequestExample` and `ResponseExample` turn their code blocks into language tabs, named by each block's `title`.
  Choosing a language is remembered and shared between the two kinds of example.
- `Panel` can hold anything, not just examples: a summary, a related-links box, a video.
- Put one `Panel` per page. A page with a panel has no table of contents column.
- Together with [`Endpoint` and `ParamField`](./api-blocks.mdx) this is enough to write an API reference by hand.

Neither example takes a `groupId`. They use fixed ones, `request-language` and `response-language`, so a reader who picks
"Node" in the request sees the Node response too, on every page. Give your blocks the same titles throughout the site
(`curl`, `Node`, `Python`) so the choice carries over.

## Accessibility and printing

A `Panel` is an `aside` labelled "Examples", and each example is a labelled section with a heading. On a phone, and on
paper, the panel is not pinned: it stays in the text where you wrote it, and every language tab is printed.

Use [CodeGroup](./code-block.mdx) directly for tabs of code that are not requests and responses.
