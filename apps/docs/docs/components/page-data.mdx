Two components draw on what dockudos knows about your pages: the headings of the current page, and the links between all pages.

## InlineToc

The headings of the current page, as a list, anywhere in the page:

<InlineToc />

```mdx
<InlineToc />
```

It shows the `h2` to `h4` headings, indented by level, and each entry links to its heading. This is the same list as "On
this page" in the sidebar; use `InlineToc` when you want it in the flow of the page, such as a summary at the top of a long guide, or
on a page with a [Panel](./panel-and-examples.mdx), which takes the place of the side list.

A page with no headings renders nothing at all.

`items` lets you pass your own entries, for a component that builds a contents list from something else:

```mdx
<InlineToc
  items={[
    { id: 'install', text: 'Install', depth: 2 },
    { id: 'verify', text: 'Verify', depth: 3 },
  ]}
/>
```

The list is a `nav` labelled "Contents".

## GraphView

Every page as a node, every link between pages as a line, with the current page highlighted:

<GraphView />

```mdx
<GraphView />
```

Nodes are links, so the graph works from the keyboard: <Kbd>Tab</Kbd> moves between nodes and <Kbd>Enter</Kbd> opens one. Hover
or focus a node to see its title. The data comes from the links in your pages, found when the site is built. Hidden pages are
left out. Layout is computed in the browser and is the same every time for the same pages. Very large sites (hundreds of
pages) get a coarser layout to keep the page fast.

The graph is a purely visual extra: it has a text alternative ("N pages") and is left off printed pages, since the
sidebar and the cross-links in the text already say the same thing.

A graph needs links to be interesting: link related pages to each other in your text, and the picture will show the
shape of your documentation, including pages nothing links to.
